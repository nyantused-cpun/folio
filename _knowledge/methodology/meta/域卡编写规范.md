# 域卡编写规范（社区示例骨架）

> **社区示例**——域卡治理件骨架。配合 `../domains/` 三张示例卡阅读。

## 三原则

1. **一个域一张卡**：域的边界以"领域划分"基准为准，卡内不跨域展开。
2. **视图完备**：BA/DA/AA/TA 四视图齐备，缺视图即缺半边思考。
3. **证据可溯**：痛点表与硬口径段每条带证据来源（真实卡）或"虚构示例"
   标注（示例卡）。

## 四字段（AI 调节断言力度的必要字段）

类型 / 版本 / 领域基准 / 关联能力卡——写在卡头引言区。

## 标准结构（九段+扩展）

1. 域概述 → 2. 三维定位 → 3. L2→L3 清单 → 4. 四视图 → 5. 常见痛点 →
6. 硬口径（证据）/ 行业合规与监管约束 → 7. 智能化机会 → 8. 关联卡片 →
9. 版本与维护（扩展段：10. Inbox 新材料证据，随材料滚动追加）。

## 反例对照

- 只列功能清单没有四视图 = 采购清单，不是域卡。
- 痛点没有证据列 = 观点堆砌，AI 会把它当事实注入方案。
