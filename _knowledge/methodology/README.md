> 真实客户证据。各方法件在此为骨架条目，按需自行充实。
> 结构与主项目方法论一致（目录页式导航 + 五拍推理链）。

## 二、五拍推理链（一行速览）

**动作还原**（客户在做什么事）→ **成本归因**（这件事贵在哪/慢在哪）→
**断点显影**（业务与系统的断点在哪个环节）→ **组件映射**（断点对应哪些
系统能力件）→ **串联成链**（组件按业务流串成方案叙事）。

## 三、引用协议（AI 如何读本层）

1. 通过路径 + `#锚点` 引用，**锚点指针 + 一行摘要**（受控冗余），全量内容不内嵌。
2. 证据纪律：条目携带来源引用（file:/decision:/user:），无出处的结论不得进入
   方案正文；未核实数字一律降级为定性表述。
3. 冲突裁决：本文件与各方法件冲突时，以方法件为准；方法件之间以推理链为纲。

## 四、写法纪律（三原则）

1. **客户视角第一人称**：痛点与要求以客户视角引述，不用第三方分析腔。
2. **概念先讲通再使用**：任何本体概念/内部代号先人话讲通，再进入方案正文。
3. **结构先行**：页面骨架（版式+组件）先定，内容后填——案例卡的"页面结构
   指纹"即结构事实源。
