# 兰亭（Folio）· 产品说明 v4.0（DSH 原生版）

> **装进 DSH 的材料生成引擎**——15 个原生工具 · 会话协议自动执行 · 换方法论不换引擎
> v4.0 · 2026-08-15 · 配套《技术白皮书 v4.0》

## 1. 摘要

**一条命令装好 15 个原生工具，会话纪律机器执行。**

兰亭（Folio）是给咨询顾问用的材料生成引擎。它把「写方案、做 PPT、报价、记住每个客户」这套长活拆成五段，机械的部分全部交给确定性代码，你只做判断和确认。

| 指标 | 值 |
|---|---|
| 原生工具 | 15 个（记忆面 9 + 质量面 6） |
| 配置起步 | 0 个 key（读图与搜索由 DSH 原生补位） |
| 会话收尾 | 事件自动执行（会话关闭自动存档） |

三大卖点：

- **深度适配 DSH**：工具、守卫、模式、事件四样全走官方扩展面，不 fork 内核
- **方法论可换**：Folio Packs 换行业只换方法论包，第三方只写 YAML 与手册
- **极致特化**：20 页材料进，四格式带质量门出，每份产出过 5 道机械检查

## 2. 为什么是 DSH

**三个 GUI 工具改不了的地方，DSH 都能改。**

| 痛点 | 影响 | 兰亭的回答 |
|---|---|---|
| 改不了给 AI 的提示词 | Codex 类工具写死 | 兰亭模式是版本可控的配置：换人、换工作方式、换行业，三层独立换装 |
| 工具是命令行黑盒 | 参数靠猜，报错靠读 | 15 个命令变成带参数校验的原生工具卡，写错就被拦下并告知 |
| 会话纪律靠 AI 自觉 | 忘跑保存、忘跑审计 | 新会话自动提醒入口协议；会话关闭自动保存客户档案 |
| 记忆两套对不上 | 宿主日志与客户档案脱节 | 客户名从工具调用自动提取，会话关闭自动归入档案 |

## 3. 五层架构

**内核一行不改，DSH 层做厚。** L0 内核保持平台无关（Trae、Kimi 同样可用）；L1-L4 是 DSH 原生插件层，全部走官方扩展面。

| 层 | 内容 |
|---|---|
| L4 方法论层 · Folio Packs | skill 即方法论 · 轻量/标准/深度三档 · 第三方只写 YAML |
| L3 事件层 · 会话协议 | 新会话自动提醒 · 会话关闭自动保存 · 客户名自动提取 |
| L2 工具层 · 15 原生工具 | 记忆面 9 个 · 质量面 6 个 · 参数校验加结构化返回 |
| L1 模式层 · 兰亭 preset | persona 自定义 · 五段 SOP 注入 · minimal 蓝本 |
| L0 内核层 · 63 命令 | 确定性渲染 · 质量门禁链 · 平台无关 |

## 4. 一段真实协作

**材料进，方案出，8 步全程机械兜底。**

1. **入口协议**——新会话自动提醒，判层级加召回
2. **材料入库**——建档、切片、双路索引
3. **追问确认**——拿不准就问，引用原文
4. **写骨架**——spec 门禁，没确认不生成
5. **生成 HTML**——同源出 PPT 工程
6. **机械质检**——格式、覆盖、独立审稿
7. **你确认转 PPT**——原生形状，客户可改
8. **自动存档**——会话关闭自动保存

## 5. 三种用法对比

| 场景 | DSH 原生（v4） | CLI 外挂（v3） | 其他 GUI |
|---|---|---|---|
| 查客户状态 | folio_status 工具卡 | pwsh 敲命令 | AI 自己翻文件 |
| 生成前确认 | spec 门禁加工具提示 | spec 门禁靠 AI 记得 | 无此机制 |
| 会话结束 | 事件自动保存 | AI 记得才跑 | 无此机制 |
| 改 AI 提示词 | preset 配置文件 | 改说明文件全文 | 改不了 |
| 拦截违规操作 | 守卫插件机械拦 | 靠约定自觉 | 无此机制 |

## 8. 怎么开始

1. **装**：跑 `setup/install.ps1`（内核）→ `setup/install-folio-plugins.ps1 -Install`（插件层）→ 重启 dsh web
2. **用**：新会话自动出现入口协议提醒，问「你有哪些 folio 工具」即可上手
3. **换**：换行业装对应 Folio Pack，换工作方式改 preset 的 SOP 段
