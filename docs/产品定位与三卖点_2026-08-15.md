# 兰亭（Folio）· 咨询/汇报材料生成引擎：产品定位与三大卖点

> 日期：2026-08-15（2026-08-16 修订）· 性质：开源筹备纲领（L4 决策固化）
> 决策依据：产品命名与三卖点定位 / 能力插槽制 / Folio 定名（内部决策记录，发布版不随附）

## 1. 一句话定位

**材料生成引擎 + 可组合方法论包，首发深度适配 DSH。**

- **品牌**：中文名「兰亭 · 咨询/汇报材料生成引擎」，英文名 **Folio**（对开本/作品集——把材料装订成册）。「售前助手」仅作内部工作区名，不对外。
- **内核**：极致特化的长程任务执行——五段价值链（§2）从材料到四格式交付物全链路确定性化。
- **扩展**：方法论可换可组合（Folio Packs），欢迎社区发布。
- **渠道**：DSH 插件化首发（skill 原生 / 命令工具化 / 会话事件 / 守卫插件 / preset）。
- **配置哲学**：零配置起步、逐级解锁——能力插槽制（宿主脱钩 + 声明制 + 外部插件可补位），见 [能力配置引导_v1_2026-08-15.md](能力配置引导_v1_2026-08-15.md)。

## 2. 产品结构：五段价值链

五个模块 = 用户用 Folio 时依次发生的五件事。句式统一为动宾，必备性只有「必需/可选」两档（可选仅精排一处）。

| # | 模块 | 英文名 | 一句话 | 里面有什么 |
|---|---|---|---|---|
| 1 | **接入材料** | Intake | 把客户扔进来的材料变成可检索的资产 | 新客户建档 · inbox 归档 · 招标/PDF/PPT 解析 · 切片 · 双路索引 |
| 2 | **建立记忆** | Chronicle | 跨会话记住项目事实与决策 | 决策记录 · 客户档案 · 世界书图 · 语义召回 · 精排（可选）· 会话保存/压缩 |
| 3 | **应用方法论** | Craft | 按可替换的方法论框架把材料拆成事实 | skill 路由 · 场景大纲 · 主题守卫 · 去 AI 化（可换包） |
| 4 | **生成产出** | Press | 从事实渲染成四格式交付物 | spec 协议 · HTML/PPTX/DOCX/报价 · 33 图/10 构件/16 版式 |
| 5 | **守住质量** | Proof | 机械检查 + 独立审查双层防幻觉 | confirmed 门禁 · verify · review · cite-audit · 主题覆盖 · 美学观察 |

> 英文名连起来是一条制书流水线（收稿 → 编年 → 章法 → 付印 → 校样），呼应 Folio「对开本」品牌；也是 v0.2 `src/` 包结构规划名（`folio.intake`/`folio.chronicle`/`folio.craft`/`folio.press`/`folio.proof`）。中文名平实，是经过实践的五段名。

**不入五段的两件事**：会话启动（session-start）是入口，不是价值链的一段；部署（安装脚本、doctor 自检、DSH 集成、能力分级）在 README 单列「部署」节。

## 3. 三大卖点与关系

| # | 卖点 | 角色 | 一句话可证伪标准 |
|---|---|---|---|
| 3 | 极致特化的长程任务能力，围绕生成材料的方方面面 | **地基**（值不值） | 20 页客户材料进 → 五段价值链 → 四格式带质量门自动出，会话结束自动 save/audit |
| 2 | 核心方法论可换可组合，欢迎社区发布方法论包 | **架构**（能不能长大） | 第三方不碰代码、只写 YAML + SKILL.md，就能发布一个市场营销方法论包，validate 过、全链路跑通 |
| 1 | 深度适配 DSH 的插件化 | **渠道**（从哪开始） | 一条命令装好 preset + skills + 守卫插件，会话内 15 个高频命令原生工具化 |

- **卖点映射五段**：卖点 3 = 模块 1+2+4+5；卖点 2 = 模块 3；卖点 1 = 部署节。
- 对外讲 **1→2→3**（故事：从哪装 → 怎么扩展 → 为什么好用）；对内建 **3→2→1**（因果：引擎 → 方法论 → 分发）。

## 4. 与 AI 产品及模型的协作方式

**总原则：引擎做机械的，宿主 AI 做判断的，云端模型做按需补位的。** Folio 给宿主 AI 外挂一层确定性执行——AI 不选工具，只调封装好的命令（对应 TECH_SPEC §3 设计哲学）。凡是「错了要重来、客户可见、可复现」的环节全部引擎化，模型只在判断/理解/生成语言处出手。

| 模块 | 宿主 AI（DSH agent）做什么 | Folio 引擎（确定性代码）做什么 | 云端模型（按需）做什么 |
|---|---|---|---|
| 接入材料 | 判断材料归属、发起入库 | 建档、切片、建索引、归档 | 招标解析的 LLM 提取（DSH 下可由宿主自做） |
| 建立记忆 | 说「记一下」、发起召回、引用证据 | 写决策/世界书/索引、BM25+RRF 融合 | embedding（语义召回）、rerank（精排，可选） |
| 应用方法论 | 读 skill、按大纲拆材料、追问澄清 | 注入主题铁律、去 AI 化预检 | —（方法论是知识资产，不靠模型生成） |
| 生成产出 | 写 spec（结构化契约）、确认 | 确定性渲染四格式（同源双输出） | —（渲染是代码不是模型） |
| 守住质量 | 读报告、修正问题 | verify/门禁/主题覆盖/美学观察 | 独立审查 LLM 会话（可换 DSH 子代理，零 key） |

- 云端模型全部走**能力插槽**：缺 key 降级不崩溃；DSH 下读图/搜索/独立审查大量由宿主原生替代，用户 0 key 起步。
- 这张表是卖点 3「极致特化」的实现方式：**特化 = 把长程任务里所有确定性环节从模型手里拿过来，模型只留下它不可替代的部分——判断。**

## 5. 四条边界决策（钉死，防止卖点互斥）

1. **DSH 是首发深度适配，不是架构押注。** 深度适配用 DSH 原生扩展机制（skill / 命令工具化 / 会话事件 / Cordis 守卫），实现层适配不污染内核；内核维持平台无关（Trae/DSH/Kimi 已验证）。表述口径：「DSH 首发、宿主无关内核」。
2. **方法论包必须携带门禁参数。** 换领域不只是换大纲和约束，还要换质量门参数（对比表行数上限、页面容量预算、主题覆盖关键词、评测集 golden_queries）。否则换了领域 verify 链会误杀或放水——「跑得出来」不等于「质量不坍塌」。
3. **机制入内核、内容入包。** 以去 AI 化为例：检测机制（style-check / review 维度）是内核；语感样本随包走（营销文案与售前方案的语感不同）。这条边界划不清，「可组合」就是口号。现成的先例：`aliases extends` 继承机制 = 包依赖。
4. **特化对象是任务域，不是行业。** 特化的是「长程材料生成」这件事（五段价值链），不是信息化咨询。通用引擎做不好的（客户知识管理、确定性渲染、质量门禁链）是内核；通用引擎做得好的（读图/OCR/搜索/通用推理）交给 DSH 原生，不重复造轮子。信息化咨询 = 默认包（default pack），非内核一部分。

## 6. 方法论包契约要点（待设计，本文档定方向）

- 包内容：大纲（outlines）+ 约束清单（主题守卫词表）+ 门禁参数 + 语感样本/禁词 + 可选组件（报价引擎、招标解析为信息化包专属）+ 评测集
- 包声明：`domain-pack.yml`（manifest），内核提供 `domain-pack validate` 机械校验——没有校验，第三方包无法自证可跑
- 包组合：粒度分级（全包 / 只提供大纲的半包 / 只提供样式的皮肤包），降低贡献门槛
- 冷启动：第一个第三方包由作者自己写——市场营销冒烟包（公开案例当材料，跑通 new → outline-to-spec → spec-gen → html-build → pptd-build 全链路），README 里跑通 demo 比「欢迎社区」有用

| 角色 | 命名 |
|---|---|
| 内核英文名 | **Folio**（对开本/作品集——材料装订成册） |
| 中文官方名 | 兰亭 · 咨询/汇报材料生成引擎 |

> 弃用原因：Evergarden（京都动画注册商标 IP 风险）、Flora（flora.ai 重名）、Lanting（与 Lantay 混淆）。
