# 能力配置引导 v1：装完后每个能力怎么选

> 日期：2026-08-15 · 读者：安装本引擎的用户（发布后随 README 分发）
> 一句话：**零配置能跑，一个 key 上好用，不想配的槽位都可以用社区插件补。**
> 本文档说明：每个能力解决什么问题 → 建议怎么配 → 不配会怎样 → 想用别的插件替代，换什么、代价是什么。

## 0. 能力插槽总表

| # | 能力槽 | 有什么用 | 建议配置 | 零配置时 | 外部替代 |
|---|---|---|---|---|---|
| 1 | 文本切片 + BM25 检索 | 把长材料切成可检索片段，字面检索历史材料——记忆基础 | **无需配置**（本地 jieba） | 完整可用 | 无（内置即零依赖） |
| 2 | 语义索引 Embedding | 让"说那个做化工的客户"也能召回"蓝海集团"；BM25 只能命中字面词 | 配 1 个 embedding key | 召回降级为纯 BM25，仍可跑，模糊查询会漏 | 社区 RAG 插件（见 §2） |
| 3 | 精排 Rerank | 在召回候选里再挑最相关的前 5 条，提高给生成环节的证据精度 | 配 1 个 rerank key（可选） | 返回融合原序，多数场景够用 | DSH 子代理精排（见 §3） |
| 4 | 读图 | 把图片转成文字描述/逐字 OCR，喂给纯文本模型 | **DSH 下零配置**（宿主原生） | 宿主接管，无需 key | 社区视觉插件（见 §4） |
| 5 | 搜索 | 查最新行业信息/竞品/官方文档，给材料里引用的外部事实找来源 | **DSH 下零配置**（宿主原生） | 宿主接管，无需 key | 社区抓取插件（见 §5） |
| 6 | LLM 提取/审查（spec-gen、材料解析、独立审查等 5 个命令） | 从材料提取事实、生成 spec、对抗性审查产出 | **DSH 下零配置**（宿主 agent 自己执行） | 宿主接管 | 独立 CLI 版才需配 1 个 chat key |

## 1. 文本切片 + BM25 检索（槽位 1：零配置，内置即完整）

**有什么用**：引擎的第一层记忆。所有客户材料进来先切片，之后按字面词快速定位"上次聊过 ERP 集成"。这是决策记忆、召回、生成引用的底座。

**建议**：什么都不用做。本地 jieba 分词，无 key、无网络。

**不用补**：它是唯一没有外部替代的槽位——因为切片和索引结构与其他能力（语义索引、世界书）是绑定的，换掉会伤根基。外部 RAG 插件可以"加一层"，但不能"换掉它"。

## 2. 语义索引 Embedding（槽位 2：一个 key，解锁语义召回）

**有什么用**：BM25 的字面匹配解决不了"换个说法就找不到"的问题。配了 embedding，问"化工行业那个客户"能召回"蓝海集团"。这是从"能用"到"好用"的一步。

**建议**：配 **智谱 embedding-3** 或 **硅基流动 BGE-m3** 任选其一。两个都是 API 按量付费，个人用量月成本通常几块钱。

**不配会怎样**：召回自动降级为纯 BM25（已有降级矩阵），引擎照常运行。知识库小（几十份材料）时不配也没关系；材料过百份后建议配。

**想用外部替代**：可以接社区知识库插件（如 [dsh-deeptutor](https://github.com/TecFancy/dsh-deeptutor)）。**代价**：外部 RAG 不带本引擎的客户隔离、别名体系、世界书图扩展——你会得到一个"通用 RAG"，但丢掉长程任务能力的三分之一。

## 3. 精排 Rerank（槽位 3：可选，锦上添花）

**有什么用**：召回返回 10 条候选时，精排挑出最相关的 5 条。直接受益者是"生成阶段的证据注入"——证据越准，产出引用越稳。

**建议**：小知识库**不配**。知识库变大、召回开始"前面几条不对"时，配硅基流动 BGE-reranker-v2-m3。

**不配会怎样**：返回 RRF 融合原序。融合序本身已经不错，多数场景够用。

**想用外部替代**：社区目前**没有** rerank 类插件。可以用 DSH 子代理做"插件级替代"——把候选列表丢给 subagent 让它挑 top5。**代价**：每次查询多一次子代理调用，慢一个量级；适合偶尔用，不适合每查必跑。

## 4. 读图（槽位 4：DSH 下零配置）

**有什么用**：把客户发的截图/票面/合同照片转成文字，给纯文本模型当上下文。两种精度：逐字 OCR（表格、金额、条款编号）和语义描述（趋势、版式、美观度）。

**建议**：**DSH 下直接用宿主原生能力**（`read_image` / `image_ocr`），零 key。这也是本引擎"深度适配 DSH"的设计——宿主已经免费提供的能力不重复收钱。

**什么时候配视觉 key**：换到没有原生读图的宿主（独立 CLI 版、部分 IDE）时，或需要**证据三态 + A/B 双观察仲裁**的严谨场景（本引擎的 `vision-describe` 提供：visible_fact/image_candidate/unknown 分级 + 双轮分歧仲裁，防编造）。内置视觉 provider 默认 MiniMax，也可用 `vision-describe --provider` 指向其他 OpenAI 兼容视觉端点。

**想用外部替代**：社区有 [dsh-vision-toolkit](https://raw.githubusercontent.com/Anionex/dsh-vision-toolkit/main/README.zh.md)、[dsh-plugin-deepeye](https://www.npmjs.com/package/dsh-plugin-deepeye)、[dsh-qwen-mm](https://ghproxy.net/https://raw.githubusercontent.com/RRRosmontis/dsh-qwen-mm/main/README.md)。**代价**：换外部插件就失去证据分级与 A/B 仲裁——关键数字（金额、条款）场景不建议换。

## 5. 搜索（槽位 5：DSH 下零配置）

**有什么用**：生成材料引用的外部事实（行业数据、竞品动态、官方文档）需要有来源。搜索能力保证"引用有出处"。

**建议**：**DSH 下用宿主原生搜索**，零 key，结果直进上下文。

**什么时候配 Tavily/字节 key**：独立 CLI 版场景，或需要双引擎融合（Tavily 优先 + 字节兜底 + 英文域名加权）时。

**想用外部替代**：宿主搜索已覆盖；需要抓取网页正文可以用 [dsh-webfetch](https://github.com/withlovehub/dsh-webfetch)（零依赖 MCP，robots.txt 合规）。**代价**：无——这个槽位宿主原生和外部插件是叠加关系，不是替换关系。

## 6. LLM 提取与审查（槽位 6：DSH 下零配置）

**有什么用**：spec 生成、材料事实提取、招标解析、独立审查、洞察生成——这 5 个命令需要"读懂材料再输出结构"。

**建议**：**DSH 下零配置**。宿主 agent 已具备读图/搜索/推理能力：命令完成机械部分（切片、校验、门禁），推理部分由宿主自己执行。

**什么时候配 chat key**：独立 CLI 版（Trae/Kimi/终端），配智谱/DeepSeek/MiniMax 任一。

**想用外部替代**：不需要——这个槽位的"外部插件"就是宿主本身，这是本引擎与"每个功能都要用户配 key"的传统插件的差异。

## 7. 能力等级与配置三步

**能力等级**（装完跑 `key-doctor` 会打印当前等级）：

| 等级 | 配了什么 | 得到什么 |
|---|---|---|
| L0 | 无 | 切片 + BM25 + 生成渲染 + 质量门禁（DSH 下读图/搜索/LLM 仍可用） |
| L1 | +1 个 embedding key | 语义召回 |
| L2 | +1 个 rerank key | 精排证据 |
| L3 | +读图 key + 搜索 key | 独立 CLI 版全量（跨宿主兜底） |

**三步**：① 复制 `.env.example` 为 `.env`（每条注释写明"解锁哪级、可空"）→ ② 跑 `key-doctor` 看当前能力等级 → ③ 按上面各节建议决定补哪个槽。

## 8. 一个原则，贯穿全文

**零配置起步，逐级解锁；每个槽位可换，但换之前知道代价。** 本引擎内置实现的槽位（切片、语义索引、精排、读图）彼此联动（客户隔离、别名、世界书、证据分级），外部插件是"补位"不是"换脑"。缺什么能力补什么插件，是社区的玩法；而"补完还能和长程任务能力协同"，才是装这套引擎的理由。
