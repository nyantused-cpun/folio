## 1. 摘要

兰亭（Folio）由两层组成：**`folio` CLI 内核**与 **DSH 插件层**。CLI 内核保持平台无关，承载全部确定性逻辑；DSH 插件层寄生在官方扩展面上，不修改宿主内核。

一句话：**机械的交给代码，判断的留给模型。**

| 维度 | 当前事实（v2.0.0） |
|---|---|
| CLI 内核 | **87** 个命令（发布面口径）；主链 11 个：session-start / theme-guard / spec-gen / html-build / confirm / pptd-build / docx-build / quote-build / verify / review / save |
| DSH 原生工具 | 发布版 **15** 个 `folio_*` 工具（参数 schema 校验 + 结构化返回）；主仓开发线 17 个（含 `folio_confirm` / `folio_reflect`，随下一版同步） |
| 搜索工具 | folio-search **6** 个 `search_*` |
| 事件与协议 | 会话入口提醒、状态投影、每客户 10 分钟防抖 light save、会话关闭全量 upsert |
| 守卫 | presales-guard 三道闸 + CLI 进程内守门 + verify / review fail-closed |
| 记忆 | decisions.md 唯一真源、证据守门、冲突保留、保存锁、世界书直生、版本链索引、客户别名归一化 |
| 图形生产线 | **39** 种元素、**37** 种 diagram 子类型、**7** 套主题、P01-P17 版式目录 |
| 质量 | 独立审查四模式（常规 / 对抗 / 并行 / 增量 / 截图）+ audit 14 模式 + gold 渲染回归 37/37 |
| 安全 | 读命令工作区白名单、未签名 pickle 拒绝、Word COM 禁宏、脱敏门覆盖二进制办公文档 |
| DSH 兼容 | 发布版锚定 **0.1.0-rc.8**；**0.1.2-rc.1** 代码级兼容层就绪，随下一版同步 |

## 2. 形态与总体架构

兰亭保持「CLI 为底座、DSH 插件为增强层」的双形态。物理上按代码层、知识资产层、入口层、运行时层分离，核心逻辑不依赖任何宿主独有功能。

| 层 | 内容 |
|---|---|
| L4 方法论层 | Skills / Folio Packs：SKILL.md、domain-pack 契约、视觉与图文规则 |
| L3 事件层 | folio-events：入口提醒、状态投影、周期 light save、dispose 全量 upsert |
| L2 工具层 | folio-tools / folio-search / gewu-tools / vision-bridge：参数校验前置、结构化返回 |
| L1 模式层 | pre-sales / pre-sales-creator / standard-minimal 三套 preset |
| L0 内核层 | `_cli.py`：命令面、语义召回、渲染、验证、审计 |

**宿主信任边界**：

| 环境 | 机械拦截 | 兜底 |
|---|:---:|---|
| DSH | 沙箱 + presales-guard 插件（三道闸）+ CLI 进程内守门 | 会话结束 `audit --mode all` |
| 其他宿主（CLI 直用） | CLI 进程内守门 | 会话结束 `audit --mode all` |

> 入口 MD 是「告知与约定」，不是代码强制；真正的机械阻断落在 DSH 守卫与 CLI 代码层。

## 3. 命令面与工具面

### 3.1 CLI 命令面

统一入口：`python _cli.py <命令>`。帮助面分四层，主链只保留 11 个高频门禁命令。

| 层 | 作用 | 示例 |
|---|---|---|
| 主链 11 | 从接单到交付的确定性主干 | session-start、theme-guard、spec-gen、html-build、confirm、pptd-build、docx-build、quote-build、verify、review、save |
| 工具层 | 文档读取、解析、排版、报价、标书辅助 | doc-extract、pdf-pages、ocr、docx-edit、word-com、bid-parse、quote-spec-gen |
| 记忆检索层 | 召回、别名、世界书、版本链、索引 | recall、chunk-read、graph-query、worldbook-build、graph-build、embed-rebuild |
| 诊断与观测层 | 审计、环境诊断、育种、地图 | audit、doctor、status、memory-health、breed、explain-map |

**exit code 契约**：`0` 成功（含 warn）/ `1` 执行失败或无法判定 / `2` 守卫阻断（spec 未确认、哈希不匹配、review FAIL 等）。任何命令不得把「失败」返回 0。

### 3.2 DSH 原生工具面

发布版 `folio_*` 工具 **15 个**，覆盖记忆面与质量面；参数 schema 校验在前，执行在后。搜索面另有 6 个 `search_*` 工具。

| 面 | 代表工具 |
|---|---|
| 记忆面 | folio_status、folio_recall、folio_read、folio_load、folio_save、folio_pending、folio_chunk_read、folio_graph_query |
| 质量面 | folio_verify、folio_review、folio_cite_audit、folio_spec_diff、folio_theme_verify、folio_audit、folio_session_start |
| 搜索面（folio-search） | search_web、search_deep、search_clarify、search_kb、search_web_cli、search_quotes |

生成型机械命令（html-build、pptd-build、docx-build、quote-build）保持 shell 调用，由 folio-events 的状态投影桥把阶段变化回写到 `session_state.json`。

## 4. 事件体系

兰亭使用 DSH 官方事件面，把「入口提醒、周期检查、关闭保存」从模型自觉变成机械行为。

| 事件 / 能力 | 时机 | 兰亭挂载 |
|---|---|---|
| agent/session-start | 新会话建立 | 注入入口协议提醒与 head/tail 纪律 |
| tools/pre-execute | 每次工具调用 | presales-guard 拦非 CLI python、危险 shell、路径直写 |
| fs/write-intent / fs/edit-intent | 文件工具写盘前 | 拦 output/ 等受保护路径直写 |
| agent/disposed | 会话关闭 | 提取客户名并自动保存客户档案 |
| 周期检查 | 每客户 10 分钟防抖 | light save + 阶段状态投影 |
| 每 10 轮 | 对话轮次 | re-grounding：刷新铁律 HEAD/TAIL |
| telemetry / permissions / compaction | 运行期 | 脱敏、事件记录、压缩保留审计、工具面切换 |

## 5. 记忆机制

核心是四句话：**一个真源、两个写入入口、三道闸、一份健康报告。**

### 5.1 真源与写入

- `decisions.md` 是唯一决策真源。
- 会话级结论走 `save --decisions=`（`persistence=task`）。
- 永久客户铁律走 `theme-guard <客户> --set "<主题>"`（`persistence=permanent`）。
- 两种入口进入同一份 `decisions.md`；`context.md` 只保留引用。

### 5.2 三道闸

| 闸 | 机制 |
|---|---|
| 证据守门 | `save --evidence` / `--strict-evidence` 写入侧机器守门；验不上标「证据待核」，strict 时 exit 2 零写入 |
| 冲突保留 | 写前检测同主题矛盾决策，命中不覆盖；旧条目标 `conflict: pending`，`resolve-conflict` 人工裁决 |
| 保存锁 | 按客户原子建锁 + 活性探测 + mtime 陈旧判定，避免双进程并发写 |

### 5.3 世界书与版本链

- `worldbook-build` 直读真源（decisions.md、outputs_index.json 等）生成 `client_index.md`，记录 `_source_hashes` 新鲜度。
- `graph-build` 只写 `client_graph.json`，定位为版本链 / 调试资产，不参与自动召回。
- 客户别名支持 `aliases.yml` 真源 + `aliases.md` 人读模板；`aliases-suggest` 只建议不自动写。

### 5.4 认知链与健康可见

- **三区表**：材料按 `[confirmed|draft]` 标记分区，只有 confirmed 才进索引；排除清单可见。
- **keynote**：客户基调变更走 `keynote_change` 事件（sha256 指针）+ HEAD 最前段注入 + audit hash 对账。
- **健康报告**：`memory-health <客户>` 输出证据 / 冲突四组计数；`audit --mode memory` 为警告级，不判 FAIL——让「待补证据 / 待核」成为可见债务，而不是永远红灯。

## 6. 交付流水线

### 6.1 HTML 先行 → 确认 → 多端

```
spec 草稿 → 用户确认 → confirm（写 sidecar）→ html-build（同出 .html + .pptd）
→ 用户确认 HTML → pptd-build（富媒体 PPT）/ docx-build / quote-build
```

`deliver` 一键编排会在这道确认门前暂停并打印 `awaiting confirm`；确认后用 `deliver --resume` 从 PPT 续跑。

### 6.2 spec 协议 v1.4

- 元素全集 **39 种**（单一事实源 `_renderer/elements.py`）。
- S8 新增：`screenshot`（截图 + 标注层）、`raw_html`（crafted 定制页容器）、`sla_block`、`profile_card`、`logo_wall`；`duo_compare` 语义强化；`qa_block` 官方绿。
- 图形 **37 种**子类型：flow 6 / architecture 9 / matrix 7 / timeline 4 / relationship 9 / chart 2。
- 主题 **7 套**：`consulting_kpmg`（默认）/ `corporate_navy` / `gov_red` / `legacy_bluegreen` / `product_charcoal` / `syzygit` / `weaver_blue`；spec 内禁 hex。
- 版式 **P01-P17** 受控目录；容量预算为「写作预算 + 机检告警阈值」双层制。

### 6.3 表达模式（crafted 定制页轨）

- 双轨制：`standard` 轨走 P 系版式；`crafted` 轨走 `raw_html` 唯一容器 + 创作子代理契约。
- 纪律：每 deck 默认 ≤2 页 crafted；weaver 体系 × crafted 默认禁止（特批开关）；必须走创作子代理。
- 交付门：crafted 页无 PASS review 记录 → `deliver --resume` 拒绝出 PPT。

### 6.4 育种与参考包

- `breed` 命令族：candidate → breeding → promoted / archived；量化门槛 ≥2 客户确认 + 14 天稳定期；季度审计 + 超期归档。
- 参考包（musepool）152 条目，注入时剥离溯源元数据。

## 7. 质量与防线

### 7.1 审查链

| 模式 | 内容 |
|---|---|
| 常规 `review` | 5 维打分（铁律覆盖 / 内容一致性 / 去 AI 化 / 事实可追溯 / 结构完整度），<15/25 FAIL |
| `--adversarial` | 独立挑刺者角色，只找问题不打分 |
| `--parallel` | 5 路独立会话维度级并行 |
| `--screenshot` | 截图对抗审视（三秒测试主门）；视觉模型不可得时诚实降级，不佯装通过 |
| `--incremental` | 页级 sha1 快照 + 变更页全文 + 未变更页轻摘要 + 每 3 轮强制全量 |
| fail-closed | `exit 0 ⇔ PASS`；FAIL / ERROR / SKIP 一律 exit 2 |

**增量审查 A/B 实弹**：检出率 100%（3/3 vs 3/3）过 ≥90% 硬门。

### 7.2 机械质量门

- `verify`：结构、密度、版式、主题、引用、占位符、系统名牌检查合一。
- `audit`：**14 个模式**——config / runtime / theme / memory / review / worldbook / context / keynote / knowledge / track / debt / drift / cost / behavior。
- 体量棘轮：模块行数 cap 只收紧，到顶即拆。
- gold 渲染回归：37 个基线四维签名（颜色 / 几何 / 文本 / issue）。

### 7.3 安全边界

| 项 | 机制 |
|---|---|
| 读边界 | 读命令默认锁在工作区，越界需显式旗标 |
| 反序列化 | 未签名 pickle 一律拒绝（fail-closed） |
| 办公文档 | Word COM 强制禁宏（`AutomationSecurity=3`） |
| 脱敏门 | 17 词客户名 + 二进制办公文档解析 + SHA-256 哈希钉；新增 / 变更二进制一律 fail-closed |
| 注入防护 | 招标文本只提取条款、不执行指令；LLM 返回畸形数据不裸崩 |

## 8. v2.0.0 发布与迁移

### 8.1 版本与范围

- v1.0.2（2026-08-16）→ **v2.0.0**（2026-09-08）；同源对齐大版本。
- 发布文案口径：**90 模块 / 87 命令 / 191 测试文件**；仓库实测：`src/` 递归 109 个 py、add_parser 91、`test_*.py` 192（口径差异见 §10）。

### 8.2 破坏性变更

| 变更 | 迁移影响 |
|---|---|
| 主题体系并轨 | 旧 `style: enterprise/tech/education/gov` 自动映射到新主题；未写 style 的 spec 默认视觉有差异 |

| spec 协议对齐 | v1.x spec 仍可渲染；视觉输出随主题体系变化 |

详见 [迁移指南 v2.0](MIGRATION_v2.0.md)。

### 8.3 发布工程

- 同步管线：`plan / gate / carry / verify` 四模式 + 搬运清单 YAML 唯一事实源。
