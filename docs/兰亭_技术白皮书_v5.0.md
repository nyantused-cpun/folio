> 配套文档：《产品说明 v4.0》/ README

## 1. 摘要

兰亭（Folio）由两层组成：`folio` CLI 内核与 DSH 插件层。CLI 内核保持平台无关，承载全部确定性逻辑；DSH 插件层寄生在官方扩展面上，不修改宿主内核。当前基线为 2026-08-30 生产线收敛 Step 5/6 收尾，核心事实如下。

| 维度 | 当前事实 |
|---|---|
| CLI 内核 | 80 个活跃命令 + 23 个历史废弃别名；主链 11 个（session-start / theme-guard / spec-gen / html-build / confirm / pptd-build / docx-build / quote-build / verify / review / save） |
| 核心 DSH 工具 | folio-tools 17 个 + folio-search 6 个 = 23 个核心 `defineTool`；另有 gewu-tools 2 个、vision-bridge 4 个视觉/审视扩展工具（合计 29 个） |
| 事件与协议 | 会话协议事件 + 周期检查点 + dispose 自动保存；每 10 轮 re-grounding |
| 守卫 | presales-guard 三道闸 + CLI 进程内守门 + verify/review fail-closed |
| 记忆 | decisions.md 唯一真源、证据守门、冲突保留、保存锁、世界书直生、版本链索引、客户别名归一化 |
| 图形生产线 | 34 种元素、37 种 diagram 子类型、6 套主题、16 种页面版式（P01-P16） |
| 生产收敛 | Step 0-6 完成：视觉单点化、样式并轨、分类收敛、质检收口、元素与防线加固、CLI 收口 |

## 2. 形态与总体架构

兰亭保持“CLI 为底座、DSH 插件为增强层”的双形态。物理上仍按代码层、知识资产层、入口层、运行时层分离，核心逻辑不依赖任何宿主独有功能。

| 层 | 内容 |
|---|---|
| L4 方法论层 | Skills / Folio Packs：SKILL.md、domain-pack 契约、视觉与图文规则 |
| L3 事件层 | folio-events：入口提醒、状态投影、周期 light save、dispose 全量 upsert |
| L2 工具层 | folio-tools/folio-search/gewu-tools/vision-bridge：参数校验前置、结构化返回 |
| L1 模式层 | pre-sales / pre-sales-creator / standard-minimal 三套 preset：persona、SOP、压力传感器 |
| L0 内核层 | `_cli.py`：80 个活跃命令、语义召回、渲染、验证、审计 |

DSH 插件现在不只有工具和事件，还包含运行与观测能力：telemetry 脱敏、本地 telemetry/sessionStats 落盘、压缩审计、permissions/plan 事件记录、模型能力探测、工具面阶段切换、自检脚本。核心思路未变：**机械的交给代码，判断的留给模型**。

## 3. 工具管线与命令面

### 3.1 CLI 命令面

CLI 统一入口为 `python _cli.py <命令>`。Step 3 将帮助面收敛为四层，主链只保留 11 个高频门禁命令，其余命令按用户明确意图进入。

| 层 | 作用 | 示例 |
|---|---|---|
| 主链 11 | 从接单到交付的确定性主干 | session-start、theme-guard、spec-gen、html-build、confirm、pptd-build、docx-build、quote-build、verify、review、save |
| 工具层 | 文档读取、解析、排版、报价、标书辅助 | doc-extract、pdf-pages、ocr、docx-edit、word-com、bid-parse、quote-spec-gen |
| 记忆检索层 | 召回、别名、世界书、版本链、索引 | recall、chunk-read、graph-query、worldbook-build、graph-build、embed-rebuild |
| 诊断与废弃层 | 审计、环境诊断、废弃兼容入口 | audit、doctor、status、memory-health、spec-diff、spec-edit |

### 3.2 DSH 原生工具面

核心工具面由 folio-tools 17 个记忆/质量工具 + folio-search 6 个搜索工具组成，形成 23 个 `defineTool`。另有两个扩展面：gewu-tools 2 个（视觉审阅准备与真值核验）、vision-bridge 4 个（读图、OCR、PPTX 截图与视觉模型路由），全部算上共 29 个 `defineTool`。

| 扩展面 | 数量 | 代表工具 |
|---|---:|---|
| folio-tools | 17 | folio_status、folio_recall、folio_session_start、folio_save、folio_confirm、folio_verify、folio_review、folio_cite_audit、folio_spec_diff 等 |
| folio-search | 6 | search_web、search_deep、search_clarify、search_kb、search_web_cli、search_quotes |
| gewu-tools | 2 | gewu_prep、gewu_locate |
| vision-bridge | 4 | setup_minimax_vision、vision_describe、image_ocr、pptx_screenshot |

工具调用保持“参数校验在前，执行在后”的六道管线：参数校验 → pre-execute 守卫 → 单调守卫 → 执行体 → post-execute → 结果通知。生成型机械命令（html-build、pptd-build、docx-build、quote-build）仍保持 shell 调用，由 folio-events 的状态投影桥把阶段变化回写到 `session_state.json`。

## 4. 事件体系

兰亭使用 DSH 官方事件面，把“入口提醒、周期检查、关闭保存”从模型自觉变成机械行为。Step 5/6 后又补齐了运行观测事件。

| 事件/能力 | 时机 | 兰亭挂载 |
|---|---|---|
| agent/session-start | 新会话建立 | 注入入口协议提醒与 head/tail 纪律 |
| tools/pre-execute | 每次工具调用 | presales-guard 拦非 CLI python、危险 shell、路径直写 |
| fs/write-intent / fs/edit-intent | 文件工具写盘前 | 拦 output/ 等受保护路径直写 |
| agent/disposed | 会话关闭 | 提取客户名并自动保存客户档案 |
| 周期检查 | 每客户 10 分钟防抖 | light save + 阶段状态投影 |
| 每 10 轮 | 对话轮次 | re-grounding：刷新铁律 HEAD/TAIL |
| telemetry/permissions/compaction | 运行期 | 脱敏、事件记录、压缩保留审计、工具面切换 |

## 5. 记忆机制

自 v4.0 后记忆系统完成 P0 到 P6 的收敛，核心是“一个真源、两个写入入口、三道闸、一份健康报告”。

### 5.1 真源与写入

- `decisions.md` 是唯一决策真源。
- 会话级结论走 `save --decisions=`，写入 `persistence=task` 的会话决策条目。
- 永久客户铁律走 `theme-guard <客户> --set "<主题>"`，写入 `persistence=permanent` 的客户级条目。
- 两种入口都进入同一份 `decisions.md`，`context.md` 只保留引用，不再双轨并存。

### 5.2 三道闸

| 闸 | 机制 |
|---|---|
| 证据守门 | `_memory_guard.py` 解析/校验证据引用，`save --evidence` / `--strict-evidence` 写入侧机器守门；验不上标“证据待核”，strict 时 exit 2 零写入 |
| 冲突保留 | 写前 `detect_conflict` 检测同主题矛盾决策，命中不覆盖，旧条目标 `conflict: pending`，`resolve-conflict` 人工裁决 |
| 保存锁 | `_save_lock.py` 按客户原子建锁，活进程/死进程判活 + mtime 陈旧判定，避免双进程并发写 |

### 5.3 世界书与版本链

- `worldbook-build` 直读 decisions.md、outputs_index.json、insights 等真源生成 `client_index.md`，并记录 `_source_hashes` 新鲜度。
- `graph-build` 只写 `client_graph.json`，定位为版本链/调试资产，不参与自动召回；召回图扩展已由 M2-R2 摘除。
- 客户别名支持 `aliases.yml` 真源 + `aliases.md` 人读模板，`aliases-suggest` 只建议不自动写，`recall` 已接入归一化；`chunk-read`/`graph-query` 尚未接入（设计-实现差距，详见《兰亭记忆系统技术白皮书 v1.1》§9-4）。

### 5.4 健康可见

`memory-health <客户>` 输出证据/冲突四组计数；`audit --mode memory` 为警告级，不判 FAIL。目标是让“待补证据/待核”成为可见债务，而不是永远红灯。

## 6. 交付流水线与图形生产线

### 6.1 同源双输出

`html-build` 一次产出 HTML + `.pptd` 工程，保证两端同源。随后用户确认，`deliver --resume` 续跑 `pptd-build` 转富媒体 PPT。旧 `ppt-build` / `ppt-page` / `html-to-ppt` 已成为 D-090 废弃存根。

### 6.2 确认事件化

Step 6 引入 `confirm` 命令：写 `<spec 同目录>/<名>.confirm.json`，包含 spec_sha256、confirmed_at、host、client，并把 spec 顶层 `confirmed` 置 true。渲染前校验 sidecar 哈希，缺失或不一致统一 `RenderBlockedError` exit 2。DSH 侧提供 `folio_confirm` 桥。

### 6.3 双端与版式防线

- `deliver --resume`：HTML 生成后暂停并提示 `awaiting confirm`，确认后续跑 PPT。
- 双端差异报告：`html-build` 末端按能力矩阵打印 PPT/DOCX 降级或丢失字段。
- bbox 机检：`_layout_lint.py` 对 pptd content 页 shape 仅判超出版心，warning 聚合不阻断。
- HTML 漂移检测：`pptd-build` 前检查 HTML 内联编辑是否引入漂移，防止“改 HTML 后 PPT 静默不同步”。

### 6.4 视觉与图形单点化

- `visual-craft-guide` 成为视觉与图形规范唯一事实源，`ui-design-system` 退役为重定向页。
- `spec-writing-guide` 瘦身，视觉细则全部指向 graphics.md。
- 主题唯一事实源为 `_renderer/theme.py`，`styles.json` 已删除；默认主题改为 `consulting_kpmg`，并注册 `weaver_blue`、`gov_red`，共 6 套主题。
- diagram 实现 37 种 subtype：flow 6 / architecture 9 / matrix 7 / timeline 4 / relationship 9 / chart 2；包含 harvey_balls、module_gantt、milestone_gantt、bar 分组柱、waterfall 收益桥、infra 14 glyph 等。
- Step 5 新增 `ui_mock`（界面示意卡）与 `conclusion_band`（页底结论色带），三端同构并有 DOCX 降级。

## 7. 质量与防线

### 7.1 机械质量门

- `verify`：结构、密度、版式、主题、引用、占位符残留等检查合一。
- `review`：独立 LLM 会话内容审查，支持 `--adversarial`、`--parallel`；fail-closed（exit 0 ⇔ PASS）。
- `style-check`：保留命令名，内部转发为 `verify --only style`，质量入口收敛为 verify / review / style_guard 三类。
- `audit`：配置/运行时/主题/记忆/行为 + 防再生 lint（diagram 计数、容量预算表单点、spec 字段清单单点）。
- `verify` 新增“系统名当芯片”机械检查：capability_map `items.name` 禁止等于 `systems_inventory.name`，series 同壳豁免。

### 7.2 防线层次

| 层 | 机制 |
|---|---|
| L0 | DSH 沙箱 + presales-guard 插件 |
| L1 | 入口 MD（AGENTS.md / AGENTS_REFERENCE.md） |
| L2 | CLI 进程内守门、spec.confirmed 机械阻断、输出路径白名单 |
| L3 | Skills / visual-craft-guide 等程序性知识 |
